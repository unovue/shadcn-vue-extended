## Why this matters

`pnpm lint` currently exits 1 with 22 errors on an untouched checkout. Most are the lint rules complaining about **generated** files (`public/r/*.json`, `registry.json`) that should never be linted; the rest are trivial style errors in markdown/Vue sources. A failing baseline means contributors can't tell their errors from pre-existing ones, and CI (plan 004) can't gate on lint until this is fixed. This plan is a prerequisite for plan 004.

## Steps

### Step 1: Exclude generated files from linting

Edit `eslint.config.mjs` to pass ignores through antfu's first argument:

```js
import antfu from '@antfu/eslint-config'
import withNuxt from './.nuxt/eslint.config.mjs'

export default withNuxt(
  antfu({
    ignores: [
      'public/r/**',
      'registry.json',
    ],
  }),
)
```

**Verify**: `pnpm lint 2>&1 | grep -c 'public/r\|registry.json'` → `0`

### Step 2: Fix the type-import in BreadcrumbLink.vue

In `components/ui/breadcrumb/BreadcrumbLink.vue`, replace

```ts
import { Primitive, type PrimitiveProps } from 'reka-ui'
```

with

```ts
import type { PrimitiveProps } from 'reka-ui'
import { Primitive } from 'reka-ui'
```

(Match the import ordering the other `components/ui/breadcrumb/*.vue` files use — type imports first; `pnpm lint:fix` will sort if needed.)

**Verify**: `pnpm lint 2>&1 | grep -c Breadcrumb` → `0`

### Step 3: Auto-fix the remaining whitespace errors

Run `pnpm lint:fix`. This fixes trailing spaces, blank-line counts, and EOF newlines in the markdown files (and README if plan 001 hasn't rewritten it yet). Inspect the diff — it must be whitespace-only:

**Verify**: `git diff --word-diff-regex='[^[:space:]]+' -- content README.md` → no word-level changes (whitespace only); then `pnpm lint` → exit 0, `✔` no errors
